# 角色关联查询与过期授权清理

`tenant-roles/permissions/get` 与 `tenant-members/roles/get` 是管理视图：返回仍存在的关联，即使权限或角色已停用，并附带状态。有效权限计算、可分配候选和写入校验继续只接受启用项；读取管理视图不恢复任何授权。

成员角色选择器调用 `tenant-roles/assignment-candidates/page`。接口沿用角色列表的租户和数据权限过滤，逐项返回 `assignable`；即使角色仍启用，只要其任何权限超出当前操作者可分配范围，也不可新选或保留。已分配关联仍由管理视图显示，方便移除。`tenant-members/roles/set` 在事务内再次校验，候选结果不能替代最终授权判断。

`tenant-roles/permissions/set` 允许在版本匹配、角色数据范围授权通过后，移除已停用或已不在操作者权限范围内的旧关联。提交的完整目标集合仍必须全部是当前可分配权限；不能保留或重新加入过期授权。前端将这些旧关联标为不可分配，用户先从已选项移除才能保存。

| 关注点 | 决策与理由 |
| --- | --- |
| 接口契约 | 两个现有 POST+JSON 读取接口保留请求结构；响应项增加 `status`。角色权限替换接口保留 `role_id`、`version`、`permission_ids`；目标集合最多 1000。通用响应及错误码不变。 |
| 认证 | JWT；不新增公开或 PSK 路由。 |
| 授权 | 保留原有 Resource/Action、租户及数据权限检查。关联查询必须同时过滤 `tenant_id` 与逻辑删除；替换接口只校验目标集合可分配，允许删除旧越权项但拒绝保留或新增。展示停用项不等于赋权。 |
| 操作日志 | 查询不记录；替换继续使用 `tenant.role.permissions.set` 记录成功和失败，摘要只含目标权限 ID。 |
| 安全日志 | 查询不记录；替换继续使用独立的租户授权安全事件，入队失败仍按原有策略处理。 |
| 缓存 | 不新增缓存，避免关联状态和授权上限变化后显示旧快照。 |
| 分布式锁 | 查询不使用；替换继续锁定单个 `tenant:<id>:role:<id>`，事务和版本条件仍是最终一致性边界。 |
| 乐观锁 | 读取不需要；替换必须使用角色 `version`，冲突不自动重试。 |
| 审计 | 关联替换沿用数据库事务、操作者上下文和触发器维护全部审计字段；查询不修改记录。 |
| 展示 | 前端把停用项标为“已停用”，过期权限标为“不可再分配，移除后可保存”；成员角色也可移除停用关联。 |
| 测试 | 本服务 SQL mock 单测验证停用关联仍返回、按租户过滤、过期授权可删除且停用项不能重选；前端单测验证候选、只读、移除提示和保存边界。容器集成测试留在完整功能 CI 阶段。 |
| 共享能力 | 继续使用既有租户授权服务、分页候选接口和前端 `GoSelectionDrawer`，不复制基础设施。 |
| 数据字典 | 角色与权限是事务性、敏感的授权数据，不作为公共数据字典提供者。 |
